# Changelog

## [Unreleased]

### Security
- Reload `auth.keys` on `SIGHUP` (so `SIGHUP` now reloads keys and no longer stops the gateway on terminal hang-up) and `config.json` `mtime` changes (recording reload state only after valid JSON parse, logging a failed reload once per file stamp, refusing to disable auth on reload when a named or quick tunnel or non-loopback host is active, and writing `config.json` atomically via temp+rename), signal a running `keysmith serve` instance whose pidfile matches `config.json` from `key add`/`key revoke`/`key scope`, and print the restart hint only when no signal was delivered (M1).
- Re-check caller key scope against the resolved base model after effort-suffix stripping and filter effort-suffixed entries on `/v1/models` (M2).
- Namespace the CLI session map by caller fingerprint plus session ID so sessions cannot be resumed across keys (M3).
- Restrict tool-call HTTP relay upstream payloads (`relayLeg` and `HttpAdapter.rawChat`) to an explicit OpenAI chat field allow-list (including `prompt_cache_key`, `verbosity`, and `extra_body.google`, while dropping the rest of `extra_body`, `service_tier`, `metadata`, `store`, and router/override fields) (M4).
- Treat only literal `auth.enabled === false` as auth disabled, fail closed when `auth.keys` is empty, refuse to start with auth off when a tunnel is configured or host is non-loopback, and stop sending `access-control-allow-origin: *` (M5).
- Disable `?api_key=` on API routes by default and, when `auth.allowQueryApiKey` is enabled, accept it only from direct loopback clients without `cf-connecting-ip` or `x-forwarded-for` (M6).
- Normalise model case and `.` / empty path segments before matching scope patterns and warn in `key add`/`key scope --deny` when an exact-model deny is used (L1).
- Reserve realistic estimated spend (`promptChars / 4` input tokens plus requested or adapter max output tokens, and `0` output tokens for embeddings) for in-flight requests across all metered paths including the tool-call passthrough relay, and hold each reservation until its usage row is recorded (L2).
- Enforce `limits.maxConcurrent` globally in the HTTP server before `meter()` with `429 rate_limit_error` (so rejected requests do not consume `perDay` quota or write a usage row), raise the default to `32`, and treat an explicit `limits.maxConcurrent: 4` (written by older `keysmith init` and `examples/config.json`) as legacy `32` with a warning at startup and in `keysmith doctor` (L3).
- Redact `error.provider` on 403/404 responses and raw paths on 404 route errors, omit `baseUrl`/`bin` on `/v1/keysmith/routes` for scoped keys, and return only `{ ok: true }` on `/healthz` when `cf-connecting-ip` is present (L4).
- Load `config.json` with `{ mint: false }` in `key` subcommands so the first `key add` on an empty key list does not mint a hidden unscoped key (L5).
- Support SHA-256 `keyHash` entries in `config.json` and `--hash` on `key add`, mark hashed keys in `key list`, preserve identical caller IDs between plaintext and hashed keys, and document that hashed keys cannot be redacted by exact value if echoed by a client (L6).

### Fixes

- Let `creditGuardThreshold` run into Kiro's overage: it now takes a share of the plan above 0 and at most `1.25` (`1.12` holds the adapter back at 112%), and a request that names a held-back adapter gets a `retry-after` of at most 300 s instead of one that lasts until the plan resets (still named in the message).
- Take a spend cap as one total over a window of UTC days: `limits.spend.<target>: { usd, since, until }` counts the metered spend from `since` up to `until` (excluded) across the month turn, refuses once it reaches the cap and outside its window (not opened yet, or closed), and refuses every request when the window is not one; `keysmith usage` and the status page show the window.
- Fail a tool request out loud instead of answering it in text: a leg that cannot carry the request's tools (a CLI with `toolMode` off such as `kiro`, an openai-wire HTTP leg on `/v1/messages`, any HTTP leg on `/v1/responses`, an anthropic-wire leg off `/v1/messages`) is passed by inside a route and named in the usage row (`skippedLegs`), and for `tool_choice` `auto` the request ends in the last refusal of a leg that took the tools or a 400 naming each leg and why — never a plain completion without its tools (only `tool_choice` `none` is still answered in text).
- Relay a tool request on `/v1/messages` to an HTTP leg on the anthropic wire verbatim (its Messages API fields, the leg's model id and key, the client's `anthropic-beta` features without an OAuth one), and its answer back as it is, streamed or not, with its usage in the row: Claude Code's tool requests can fail over to an Anthropic API key (`claude-api`) instead of being passed by there.
- Guard Kiro's plan credits, which its runs report no token counts of: every adapter that runs `kiro-cli` is held back at `creditGuardThreshold` (0.9 by default) of the plan read from `kiro-cli chat --no-interactive --trust-tools= --agent <its agent> /usage` (cached and run at most once per ten minutes per login across processes, kept in `credit-guard.json`; `serve` keeps it fresh in the background so no request waits for it; a reading past 30 s is stopped with SIGTERM, then SIGKILL); a route passes it by, a request that names it is a 429, a virtual model's classifier is not asked, and a reading at or over the threshold holds the adapter back until the plan resets even when the readings after it fail (a failure with no reading of the period never blocks). `creditGuardThreshold` on an HTTP adapter is a load error. `keysmith doctor`, `keysmith status` and `/v1/keysmith/routes` show the guard, which legs carry tools per alias and face (a held-back leg counted out), routes where a guarded leg comes before an uncapped metered HTTP leg, and the legs requests were passed by in the last 24 h.
- Keep 504 for failures typed as timeouts (`ETIMEDOUT`, `TimeoutError`) instead of any message containing "timeout" (a regression that turned the bridge's `ready_timeout` 502 into a 504), and report a codex run stopped by keysmith's timeout while it retried its stream as that 504, not a 502 "Reconnecting...", and an HTTP upstream that went quiet after its headers past the adapter's timeout as a 504 that names the adapter.
- Derive stable non-secret account names for `{exec: ...}` credential references (`-s <service>` for `security find-generic-password|find-internet-password`, else `<program>:<hmac12>` using HMAC-SHA256 under a cached per-install 32-byte key in `account-hmac.key` with no argument text, falling back to `exec:<hmac12>` on unknown wrapper flags, and failing loudly in `serve`/`doctor` if the key file cannot be read or is invalid); existing usage rows and `limits.spend` caps keyed on `"exec"` no longer match `{exec: ...}` credentials, and `keysmith doctor` and gateway startup now warn once for `"exec"` or unmatched `<program>:<hmac12>` spend caps, naming the current account names to use instead.
