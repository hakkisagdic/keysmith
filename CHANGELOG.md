# Changelog

## [Unreleased]

### Added

- Add an opt-in in-memory exact-match cache for non-streaming `/v1/chat/completions` (`cache.enabled`, default off; `ttlSeconds` 3600, `maxEntries` 500): a repeated deterministic request (`temperature` 0, or the header `x-keysmith-cache: use`, and no tools, tool history, stream or session) is answered locally with `x-keysmith-cache: hit`, a fresh `id` and `created`, and a usage row `cache: "hit"` at cost 0. The key is a hash of the caller and the request fields that change the answer, so one gateway key never reads another's; nothing is written to disk. A bad `cache` value is a `keysmith doctor` error and the cache stays off.

- Filter recent usage rows in `keysmith usage` (`--status` `ok|error|limited|blocked|denied`, `--tag`, `--key`, `--model`, `--min-cost`, `--min-ms`, each with `--tail`) and on `GET /v1/keysmith/usage` (`status`, `tag`, `key`, `model`, `min_cost`, `min_ms`, each with `tail`). Aggregates stay whole-log. A scoped key still sees only its own rows. `--min-cost` / `min_cost` leaves out rows with no price and reports how many.

- Add opt-in outbound secret guard (`guard.secrets`: `"off" | "block" | "mask"`, default `"off"`, configurable via `keysmith config set guard.secrets <mode>`) across `/v1/chat/completions`, `/v1/messages`, `/v1/responses` and `/v1/embeddings`: scans request strings up to the 32 MB body limit for fixed secret shapes (`pem-private-key`, `aws-access-key`, `github-token`, `slack-token`, `google-api-key`, `sk-api-key`, `keysmith-key`), refuses with `400 invalid_request_error` (`status: "blocked"`) or masks matches as `[REDACTED:<kind>]` while recording `guard` and `guardKinds` in `usage.jsonl` without ever logging secret values, and fails closed to `"block"` with a `keysmith doctor` config error on unknown settings.

- Add per-key `perMinute` (rolling 60-second request limit, `429 rate_limit_error` with `retry-after`), `expires` (ISO date or date-time; date-only = `00:00` UTC, `401 authentication_error` `"key expired"`) and `disabled` (`403 permission_error` without deleting the entry) on `auth.keys` entries, managed via `keysmith key add` and `keysmith key scope` (`--per-minute` / `--no-per-minute`, `--expires` / `--no-expires`, `--disable` / `--enable`), surfaced in `keysmith key list`, `/status` and `keysmith usage`, enforced on batch `--key` and status-page login, and logged at most once per key per minute (`status: "limited"`).

- Add per-profile cheap `GET` health targets (`health` on `groq`, `mistral`, and Cloudflare's `/client/v4/accounts/{account}/tokens/verify`, overridable with `healthPath`) shared by MCP `keysmith_test` and `keysmith doctor`, raising the default timeout to 15 s and classifying `no_such_endpoint` (on health paths) separately from fallback `no_models_endpoint`, plus `timeout` (`no answer in N s`) and error-code-only `unreachable`. Response bodies are never read and no paid model calls are issued.
- Add `--allow-explicit-only` / `--no-allow-explicit-only` on `keysmith alias` (`aliasPolicy.<name>.allowExplicitOnly`) so curated chains can include `explicitOnly` legs in strict order without exposing `explicitOnly` legs to other aliases, virtual models, or fallback outside the chain; `unsafeTools` stays refused, `modelsOnly` continues enforcing declared models, and `aliasIssues` flags paid legs or unlisted `modelsOnly` targets on explicit chains.
- Add `--per-day <N>` directly to `keysmith key add` (matching `key scope`), and warn when `--allow alias:<name>` leaves none of the alias's legs permitted.
- Add an optional catalogue (`catalogue` in `config.json`) with per-adapter `requestsPerMinute`, `requestsPerDay` and `tokensPerMonth`: over a limit a local `429` with `retry-after`, a cooldown after an upstream `429`, and `source`/`tier` on usage rows.
- Add `keysmith source enable|disable <profile>` (tokenrouter, groq, mistral, cloudflare): the adapter with a Keychain key reference, out of every alias, conservative catalogue limits, discovery on; and `keysmith config get|set|unset <key>` for the top-level settings, with a dated backup first.
- Add the `cloudflare` (Workers AI) profile (`--account-id`) and the catalogue field `tokensPerDay`.
- Fix: `--help` / `-h` after any command prints that command's help and does nothing else (`add tokenrouter --help` used to attach the adapter).
- Add the `tokenrouter` and `mistral` profiles, `keysmith discover <adapter>` (free models, behind `discovery.enabled`) and the `freeOnly` adapter option.
- Add `promptCache` (`{ mode: "off"|"dry-run"|"on", ttl: "5m"|"1h", minTokens }`) on Anthropic-wire adapters: up to three `cache_control` breakpoints (last tool, last system block, the block before the final turn) on a request that has none; off by default. `keysmith usage` shows the cache read share and the list-price saving; `cacheWrite1h` is priced at 2x input.
- Add `keysmith usage record` for runs made outside the gateway (`face: "external"`, repeat-safe with `--id`).

### Security
- Reload `auth.keys` on `SIGHUP` (so `SIGHUP` now reloads keys and no longer stops the gateway on terminal hang-up) and `config.json` `mtime` changes (recording reload state only after valid JSON parse, logging a failed reload once per file stamp, refusing to disable auth on reload when a named or quick tunnel or non-loopback host is active, and writing `config.json` atomically via temp+rename), signal a running `keysmith serve` instance whose pidfile matches `config.json` from `key add`/`key revoke`/`key scope`, and print the restart hint only when no signal was delivered (M1).
- Re-check caller key scope against the resolved base model after effort-suffix stripping and filter effort-suffixed entries on `/v1/models` (M2).
- Namespace the CLI session map by caller fingerprint plus session ID so sessions cannot be resumed across keys (M3).
- Restrict tool-call HTTP relay upstream payloads (`relayLeg` and `HttpAdapter.rawChat`) to an explicit OpenAI chat field allow-list (including `prompt_cache_key`, `verbosity`, and `extra_body.google`, while dropping the rest of `extra_body`, `service_tier`, `metadata`, `store`, and router/override fields) (M4).
- Treat only literal `auth.enabled === false` as auth disabled, fail closed when `auth.keys` is empty, refuse to start with auth off when a tunnel is configured or host is non-loopback, and stop sending `access-control-allow-origin: *` (M5).
- Disable `?api_key=` on API routes by default and, when `auth.allowQueryApiKey` is enabled, accept it only from direct loopback clients without `cf-connecting-ip` or `x-forwarded-for` (M6).
- Normalise model case and `.` / empty path segments before matching scope patterns and warn in `key add`/`key scope --deny` when an exact-model deny is used (L1).
- Reserve realistic estimated spend (`promptChars / 4` input tokens plus requested or adapter max output tokens, and `0` output tokens for embeddings) for in-flight requests across all metered paths including the tool-call passthrough relay, and hold each reservation until its usage row is recorded (L2).
- Enforce `limits.maxConcurrent` globally in the HTTP server before `meter()` with `429 rate_limit_error` (so rejected requests do not consume `perDay` quota or write a usage row), raise the default to `32`, and treat an explicit `limits.maxConcurrent: 4` (written by older `keysmith init` and `examples/config.json`) as legacy `32` with a warning at startup and in `keysmith doctor` (L3).
- Redact `error.provider` on 403/404 responses and raw paths on 404 route errors, omit `baseUrl`/`bin` on `/v1/keysmith/routes` for scoped keys, and return only `{ ok: true }` on `/healthz` when `cf-connecting-ip` is present (L4).
- Load `config.json` with `{ mint: false }` in `key` subcommands so the first `key add` on an empty key list does not mint a hidden unscoped key (L5).
- Support SHA-256 `keyHash` entries in `config.json` and `--hash` on `key add`, mark hashed keys in `key list`, preserve identical caller IDs between plaintext and hashed keys, and document that hashed keys cannot be redacted by exact value if echoed by a client (L6).

### Fixes

- Run the CLI when `keysmith` is started through npm's bin symlink, or through a path whose `import.meta.url` is percent-encoded (a space or another special character). The entrypoint guard compared `import.meta.url` to `file://${process.argv[1]}`, which is false in both cases, so `main()` never ran and the process exited 0 with no output. It now compares `realpathSync(fileURLToPath(import.meta.url))` with `realpathSync(process.argv[1])`; a missing `argv[1]` or a path `realpathSync` cannot resolve is still not the entrypoint (npm on Windows launches node via a `.cmd` shim on the real file).
- Register credentials from an adapter's `headers` and `mediaHeaders` (`authorization`, `proxy-authorization`, `x-api-key`, `api-key`, `x-goog-api-key`, `cookie`, and names matching key, token, secret, auth or password — the full value and the token after a leading `Bearer ` or `Basic `) so an upstream error or a log line that echoes them is rewritten with `redactKey`. The headers sent upstream are unchanged, and a non-secret header such as `anthropic-version` is not registered.
- Refuse `keysmith tunnel run` when `auth.enabled` is false, and refuse `keysmith serve` with auth off when `host` is null, not a string, empty after trim, or not a loopback address (`listen` on a null host binds every interface). An unauthenticated quick or named tunnel no longer starts. Locking out a public tunnel that was running with auth off is intentional.
- A client `metadata.harness_id` or `x-harness-id` no longer overrides the harness named by the model string a key's scope authorised (`<adapter>/chrn_…` stays that harness). An open key that names a harness only by `harness_id` still reaches it.
- Expand `~` in `kiro-cli` binary paths (`which`/`expand`) inside the credit guard and `keyOf`/`_entry`, fail immediately (`<name> not found (looked at <expanded path>)`) instead of waiting 30 s on missing binaries, and add a 10 s `STALL_TIMEOUT_MS` check (`no output after 10 s (login prompt?)` plus the scrubbed first diagnostic line) when a login prompt or silent hang stalls `/usage` without writing stdout.
- Preserve provider token `usage` reported on partial streams when a request fails before completing (`Gateway._leg`/`collect` and `errorMarks` in `src/server.js`).
- Give a virtual model its classifier's instruction (`classifierPrompt`, or `classifier.prompt`), sent as the classifier's system message and part of the prompt cache key, so a rubric saying what `simple`, `medium` and `complex` mean lives in the config (a small local classifier went from 82–90% to 94–96% on a 50-prompt set with one).
- Add `rules` to a virtual model: a fast path tried after a session's sticky label and before the prompt cache and the classifier, where the first rule whose conditions all hold (`match`, `unless`, `maxChars`, `noTools`, `noMedia`, `noCode`) labels the request without asking the classifier (`reason: "rule:<name>"`); a rule hit is neither cached nor made sticky.
- Meter a virtual model's classifier calls like any leg: each is held to the classifier adapter's spend cap first (a refusal labels the request `medium` unasked and writes a `limited` row) and writes its own usage row (`purpose: "classifier"`, with its token counts and cost) once its reply ends, while the label is used as soon as it arrives; `keysmith chat`, `keysmith route explain` and a closing gateway wait for those rows.
- Send `reasoning_effort: "none"` to Gemini 3.8 Flash on Google's OpenAI-compatible endpoint when a request asks for at most 16 tokens and chose no effort itself (nor in `modelParams`): its default thinking counted against `max_tokens` and a classifier asked for one word got an empty reply, and `"minimal"` is refused for that model.
- Let `creditGuardThreshold` run into Kiro's overage: it now takes a share of the plan above 0 and at most `1.25` (`1.12` holds the adapter back at 112%), and a request that names a held-back adapter gets a `retry-after` of at most 300 s instead of one that lasts until the plan resets (still named in the message).
- Log one `! spend cap hit — …` error line, with the spend, when a spend cap starts refusing (and again when what it says changes), instead of refusing silently but for the usage row.
- Take a spend cap as one total over a window of UTC days: `limits.spend.<target>: { usd, since, until }` counts the metered spend from `since` up to `until` (excluded) across the month turn, refuses once it reaches the cap and outside its window (not opened yet, or closed), and refuses every request when the window is not one; `keysmith usage` and the status page show the window.
- Fail a tool request out loud instead of answering it in text: a leg that cannot carry the request's tools (a CLI with `toolMode` off such as `kiro`, an openai-wire HTTP leg on `/v1/messages`, any HTTP leg on `/v1/responses`, an anthropic-wire leg off `/v1/messages`) is passed by inside a route and named in the usage row (`skippedLegs`), and for `tool_choice` `auto` the request ends in the last refusal of a leg that took the tools or a 400 naming each leg and why — never a plain completion without its tools (only `tool_choice` `none` is still answered in text).
- Relay a tool request on `/v1/messages` to an HTTP leg on the anthropic wire verbatim (its Messages API fields, the leg's model id and key, the client's `anthropic-beta` features without an OAuth one), and its answer back as it is, streamed or not, with its usage in the row: Claude Code's tool requests can fail over to an Anthropic API key (`claude-api`) instead of being passed by there.
- Guard Kiro's plan credits, which its runs report no token counts of: every adapter that runs `kiro-cli` is held back at `creditGuardThreshold` (0.9 by default) of the plan read from `kiro-cli chat --no-interactive --trust-tools= --agent <its agent> /usage` (cached and run at most once per ten minutes per login across processes, kept in `credit-guard.json`; `serve` keeps it fresh in the background so no request waits for it; a reading past 30 s is stopped with SIGTERM, then SIGKILL); a route passes it by, a request that names it is a 429, a virtual model's classifier is not asked, and a reading at or over the threshold holds the adapter back until the plan resets even when the readings after it fail (a failure with no reading of the period never blocks). `creditGuardThreshold` on an HTTP adapter is a load error. `keysmith doctor`, `keysmith status` and `/v1/keysmith/routes` show the guard, which legs carry tools per alias and face (a held-back leg counted out), routes where a guarded leg comes before an uncapped metered HTTP leg, and the legs requests were passed by in the last 24 h.
- Keep 504 for failures typed as timeouts (`ETIMEDOUT`, `TimeoutError`) instead of any message containing "timeout" (a regression that turned the bridge's `ready_timeout` 502 into a 504), and report a codex run stopped by keysmith's timeout while it retried its stream as that 504, not a 502 "Reconnecting...", and an HTTP upstream that went quiet after its headers past the adapter's timeout as a 504 that names the adapter.
- Derive stable non-secret account names for `{exec: ...}` credential references (`-s <service>` for `security find-generic-password|find-internet-password`, else `<program>:<hmac12>` using HMAC-SHA256 under a cached per-install 32-byte key in `account-hmac.key` with no argument text, falling back to `exec:<hmac12>` on unknown wrapper flags, and failing loudly in `serve`/`doctor` if the key file cannot be read or is invalid); existing usage rows and `limits.spend` caps keyed on `"exec"` no longer match `{exec: ...}` credentials, and `keysmith doctor` and gateway startup now warn once for `"exec"` or unmatched `<program>:<hmac12>` spend caps, naming the current account names to use instead.
